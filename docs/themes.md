# 테마 확장 안내

현재 공개 테마는 `rain`(수사관 사무실의 유리창) 하나다. 기존 저장 키를 유지하고, 삭제된 테마 ID는 기본 테마로 대체한다. 테마 선택·음량은 브라우저 설정에 저장하고, 해금 여부는 플레이 데이터에서 판정한다.

## 등록과 해금

`dist/app.js`의 `themeChoices`에 테마를 등록한다. 각 항목은 고정 ID, 이름, 설명, `unlock(player, project)` 조건 함수, `presentation`을 갖는다. 설정 UI와 선택 처리에서 같은 조건 함수를 사용한다. 세이브 불러오기와 프로필 재작성 후에도 렌더링 시 조건을 다시 확인하며, 선택한 테마가 잠겼다면 기본 테마를 적용한다. 기본 테마는 항상 해금 상태를 유지한다.

실제 추가 테마·조건·해금 코드는 아직 등록하지 않았다. 숨김/잠금 표시 정책과 해금 알림도 테마를 추가할 때 정한다. 현재는 등록된 잠긴 테마가 있다면 설정에서 선택할 수 없도록 처리한다.

특전 코드 처리의 `save.perks`는 기존 내보내기·불러오기에 포함되므로, 해당 코드의 특전 ID를 해금 조건에서 확인할 수 있다. 인연 데이터 `save.bonds`는 현재 만난 인연 ID 목록이며 레벨이 아니다. 인연 레벨 조건을 넣을 때는 먼저 레벨 획득 규칙과 `engine.mjs`의 저장 데이터 검증·마이그레이션·코드 내보내기/불러오기까지 확장해야 한다. 인연을 만났다는 사실을 임의의 레벨로 취급하지 않는다.

## 시각과 효과

테마는 텍스트 상자 색상에 한정되지 않는다.

- `presentation.background()`는 배경 DOM 전체를 반환한다. 현재 `rainWeather`가 도시, 창틀, 비, 물방울, 안개를 구성한다. 새 테마는 다른 배경 구성을 반환할 수 있다.
- `presentation.touch(event)`는 터치·클릭·홀드 반복 효과를 처리한다. 현재 `rainImpact`가 청록색 파문을 만든다.
- `presentation.transition(commit)`는 다음 장면을 적용하는 콜백을 받아 Promise를 반환한다. 현재 오프닝 전환은 `prismTransition`을 사용한다. 새 효과에서도 commit은 한 번만 호출하고 busy·오버레이·스크롤·이벤트를 정리해야 한다.
- 루트의 `data-theme` 속성을 통해 패널·메뉴·텍스트·버튼·배경·효과 CSS를 테마별로 지정할 수 있다. 기존 두 추가 테마의 색상 CSS는 제거했다.

서사에 직접 연결된 6-2의 꿀밤 효과는 장면 자체의 `entryEffect`다. 캐릭터 개입 전환처럼 서사상 필수인 연출과 테마 연출의 우선순위는 새 테마를 만들 때 정한다. 현재 공개 테마의 연출은 유지한다.

추가하는 렌더러도 모션 감소 설정, 터치 반복 개수 제한, 모바일 뷰포트 대응을 지켜야 한다. 플레이어 이름·입력값을 HTML에 넣을 때는 기존 displayText/esc를 사용한다.

## 검증

`verify-player.cjs`는 삭제된 테마 복구, 해금 전 선택 차단, 조건 만족 후 선택, 배경·터치·전환 렌더러 연결, 진행 데이터 변경 후 기본 테마 복귀를 검사한다. 테스트용 테마와 코드는 테스트 안에서만 등록되며 사이트에는 포함되지 않는다. 기존 파문·프리즘·빌딩 테스트도 유지한다.

## 정적 명찰 미리보기

`themeChoices`의 `preview`는 선택 버튼 전면에 적용할 정적인 디자인 키다. 현재 `office-window`는 본 테마와 같은 `curtain-city.svg`, 청록빛 유리와 창틀을 가로형 카드로 압축해서 사용한다. 제목·설명·적용 상태는 카드 위에 표시한다. 새 테마는 이 키에 대응하는 CSS 또는 정적 이미지 구성을 추가한다. 미등록 키는 기본 정적 구성을 사용한다.

`themeNamecard`는 `presentation.background/touch/transition`을 호출하지 않는다. 실제 배경 DOM 복제, 비·물방울 노드 생성, 타이머, 캔버스, 동영상, 블러 필터를 쓰지 않는다. 카드 하위의 애니메이션·전환도 CSS로 끈다. 실제 테마의 효과는 선택 후 본 화면에서만 실행한다.

각 테마는 `englishName`(명찰 상단 영어 제목), `unlockLabel`(제목 바로 아래의 해금 조건), `note`(부연 설명)를 지정한다. 모든 명찰에 해금 조건 영역을 공통 출력하며, 테마를 추가할 때 조건 판정 함수와 실제 조건 설명을 함께 등록한다. 현재 기본 테마의 조건 설명은 ‘기본 해금’이다. 조건 설명은 조건 충족 후에도 유지하고, 적용 상태는 별도 배지로 표시한다.

## 다섯 메뉴 심볼의 흑백 전환

테마의 `presentation.symbolTone`을 `'white'` 또는 `'black'`으로 지정한다. 값이 없거나 알 수 없는 값이면 white를 사용한다. 현재 기본 테마는 white다. applyPreferences가 활성·해금된 테마를 기준으로 루트의 data-symbol-tone을 설정한다. 테마 전환·불러오기·해금 상태 변경·초기화에도 같은 규칙을 사용한다.

검은 심볼 모드는 다섯 메뉴의 원본 흰색 PNG에 CSS invert(1)를 적용한다. 알파 투명도·크기·선택/호버 상태는 유지하고, 밝은 배경에 맞춰 그림자도 검은 계열로 바꾼다. 빌딩의 기본 시각 요소로 재사용하는 동일 심볼에도 반영한다. 캐릭터 이미지·컷씬·배경·SD·명함에는 반전을 적용하지 않는다. 원본 파일은 수정하거나 복제하지 않는다. 실제 밝은 테마를 추가할 때 해당 테마에 black을 지정하면 된다.

## 종족 특성 카드의 일반·변경·약화 상태

새 테마를 만들 때 일반 종족 특성 카드와 레플리카·아종 변경 특성 카드가 같은 화면에서도 구분되도록 색을 정한다. 레플리카와 아종 변경 카드는 같은 특수 배경과 굵은 왼쪽 테두리를 공유한다.

- 일반 카드 바탕과 테두리는 `--race-trait-surface`, `--race-trait-edge`로 지정한다.
- 특수 카드에는 `--race-trait-special-surface`, `--race-trait-special-edge`, `--race-trait-special-label`을 지정한다. 일반 카드와 다른 바탕을 골라 위계가 보이게 한다.
- 종족 특성의 배경색과 테두리를 테마의 공통 패널 규칙에서 덮어쓰지 말고 위 변수를 사용한다.
- 새 테마에서는 오토마타 레플리카 및 모던·설원 엘프를 실제로 선택해 일반·변경·약화 카드가 구분되는지 확인한다. 약화 카드는 흐리게 보여도 제목과 본문을 읽을 수 있어야 한다.
